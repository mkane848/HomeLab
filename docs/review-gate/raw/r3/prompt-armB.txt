[AUDITOR'S SECTION 2 — plan/implementation contract]

The agreed implementation (from the PR body + commit `92a8ed0`):

- New endpoint **`POST /api/deck-validity`** on the commander-recommender
  server. Request: `{ "list": "<pasted decklist>", "commanderNames": ["…"] }`,
  1–2 names. Errors mirror existing routes: 400 malformed body, 404
  unresolvable commander, 503 unseeded DB.
- **Pure, seedless kernel** — `server/src/services/deckValidation.ts`
  `validateDeck(parsed, nameMap, commanders, backgrounds)` returns
  `DeckValidationResult` `{ isValid, commander: { names, colorIdentity,
  eligible, pairingLegal }, deckSize: { total, expected, isValid },
  colorIdentity: { combined, violations }, legality: { banned, notFound } }`.
  It never touches the DB; the route resolves names into a `Map` and passes it
  in, so every rules decision is unit-testable seedlessly.
- **Thin route** — `server/src/routes/deckValidity.ts`, built on the same
  conventions as `combos.ts` (`(req.body ?? {})` guard, 404 convention). Resolves
  `commanderNames` via `findCardsByNames`, 404s any name not in the map, and
  calls `validateDeck(...)` with `getBackgroundCards()` as the background pool.
- **Behavior the plan promises:**
  1. Deck size — exactly 100 cards (903.5a), counted over the **whole pasted
     deck** including banned and unparseable cards, so a 100-card deck with one
     banned card reads 100, not 99.
  2. Colour identity — every card within the commander unit's combined identity
     (903.4); identity columns are `parseJsonArray`-decoded before the
     primitives see them (they expect `string[]`, the DB stores JSON strings).
  3. Commander unit legality (903.3 / 702.124) — named commanders must be
     commander-eligible **and** form a real unit via the same
     `buildCommanderUnits` path `/api/recommend` uses, so partner / companion /
     Background pairs are validated and illegal ones rejected.
  4. Legality surface — banned and unparsed cards are reported (never silently
     dropped) and fail the verdict.
- **Out of scope:** the client-side panel to submit/render this.

Verification claims in the contract: seedless unit suite covering the rule
seams (banned/notFound still count toward size, JSON-identity decoding,
partner-pair union identity, ineligible commander, illegal pairing); an
integration suite that runs against the real seeded DB asserting
99-card `yshtola` fails size and The Tenth Doctor + Rose Tyler passes
100-card valid with `pairingLegal`; local unseeded server suite 404 passed /
0 failed, lint and `tsc` clean, coverage above thresholds.
