You are working in the ASoHaVCompanionApp repository (A Story of Heroes and Villains), a tabletop RPG companion app with an Express server in apps/server. Every campaign has one shared Party record, and the Party holds Rapport: a running count of the group's teamwork that players build up in play and spend to help each other (Aid). The track has a length that designers set in the game library (settings.RapportTrackLength, 5 by default). Under the current V0.6 ruleset, Rapport is allowed to overflow the track: the extra is banked until the next Make Camp (the party's rest step, where Rapport turns into a Party advance), and only spending Rapport early forfeits it. In apps/server/src/routes/party.ts, PUT /campaigns/:campaignId/party lets any campaign member save the whole Party document: it merges the request body over the stored party and then clamps Rapport server-side to the range 0 through RapportTrackLength, reading the library for the ceiling. There is a bug: that clamp dates from the older rules, when Rapport was a plain capped counter, so every save silently throws the banked overflow away. For example, with a track length of 5, saving a Party with Rapport 13 stores and returns 5. Fix the route so that: (1) a Rapport above the track length is kept exactly as sent, with no upper limit at all (13 stays 13, both in the response body's party.Rapport and in the object passed to saveParty); (2) a negative Rapport is still raised to 0 (-4 becomes 0); (3) an in-range value is untouched (3 stays 3); (4) everything else about the route is unchanged, including the 404 for an unknown campaign, the 403 for a non-member and the 409 for an archived campaign. Add or update tests in apps/server/src/routes/party.test.ts proving (1) through (3). The file currently has a test called 'clamps Rapport down to the track length' that sends 9999 and expects 5: that behaviour is being reversed on purpose, so replace that test instead of keeping it. Your added/updated test(s) must FAIL if only your party.ts fix is reverted while the test changes stay. The web client has a matching cap of its own that is handled separately, so leave apps/web alone. Change ONLY these two files: apps/server/src/routes/party.ts and apps/server/src/routes/party.test.ts. Do not commit. Do not touch any other file.
