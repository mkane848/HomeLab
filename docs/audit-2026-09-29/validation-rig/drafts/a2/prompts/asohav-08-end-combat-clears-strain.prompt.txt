You are working in the ASoHaVCompanionApp repository (A Story of Heroes and Villains), a tabletop RPG companion app with an Express server in apps/server. The GM (game master) runs each fight as a Combat Encounter record: it has Participants (Kind 'PC' for a Hero, a player's character, whose RefId is that Hero's character id, or Kind 'Enemy'), a Status of 'Active' or 'Ended', and a History log of { Id, At, Text } entries, newest first. A Hero's Strain, the harm marked during a fight, lives on the Hero's own character sheet, a separate record from the Encounter: CharacterSheet.Strain is an array of booleans, one per Strain box, true meaning marked. The ruleset (V0.6, 'Ending Combat') says that when Combat ends all Strain is cleared, while Statuses remain. In apps/server/src/routes/combat.ts, POST /campaigns/:campaignId/combat/:encounterId/end is the GM-only route that ends a fight. There is a bug: it only flips the Encounter's Status to 'Ended' and saves the Encounter. It never reads or writes the Heroes' sheets, so every Hero leaves the fight still carrying the Strain they marked and starts the next one with it. Fix the route so that, besides ending the Encounter as it does today: (1) for each participant of Kind 'PC' it loads the Hero's sheet with getSheet(participant.RefId) from the repo module, once per Hero participant, skipping Enemy participants and any participant whose sheet comes back null; (2) a sheet that has at least one Strain box marked is saved with saveSheet(sheet, campaignId), where the first argument is that sheet with every Strain entry set to false (same number of boxes, every other field unchanged) and the second is the campaign's id; (3) a sheet with no Strain marked is not saved at all; (4) a new History entry whose Text contains 'Combat ended', shaped like the one the /start route creates, is added at the front of the Encounter's History, and the response is still 200 with { encounter } showing Status 'Ended'; (5) a non-GM is still refused with 403, and no sheet is read or written. Add or update tests in apps/server/src/routes/combat.test.ts proving (1) through (5); note that the file mocks the repo module with a vi.mock factory listing each repo function the routes use, and builds Encounters with makeEncounter(). Your added/updated test(s) must FAIL if only your combat.ts fix is reverted while the test changes stay. Change ONLY these two files: apps/server/src/routes/combat.ts and apps/server/src/routes/combat.test.ts. Do not commit. Do not touch any other file. When done, run `npx vitest run src/routes/combat.test.ts` from apps/server and make sure it passes.
