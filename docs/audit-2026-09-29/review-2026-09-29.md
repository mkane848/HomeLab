## 3. The metric is not the job being staffed

- Harness PASS = scope + suite + failsOnOld, where failsOnOld needs the MODEL'S OWN test to fail on reverted source (`test-tasks.ps1:748-783`). `docs/target-setup.md:66-71,83-91` says the target executor must NOT write tests: the planner supplies the acceptance test and the executor edits source only (milestone 3, "expected to be the largest single jump", not built).
- lfc-03 is the only task with an owner acceptance block. 15 runs (acc.py): 7 pass all gates, 9 pass owner acceptance, 6 both; 3 right-fix-wrong-test runs (devstral-small-2, north-mini 09-26, qwen3.5) and 0 gate-passes with a wrong source. Owner acceptance 9/13 measured runs vs all-gates 6/13. The gate never over-credited source on lfc-03 but under-credits it by a third.
- The upstream fix commit's test file exists for every mined task (that is how failsOnOld was verified at mining time), so `acceptance` could be extended to all 8 other tasks at almost no authoring cost.

## 7. Harness findings surfaced while mining candidates

1. **`srcRevertFiles` with 2+ entries cannot be graded.** `test-tasks.ps1:759` passes `@($tk.srcRevertFiles)` nested inside the argument array to `Run-Native`, whose parameter is `[string[]]$Arguments` (`:165`), so git receives ONE argument `src/a.ts src/b.ts`. Reproduced in pwsh 7 (`verify/nested.ps1`): 1 file -> `[src/a.ts]`; 2 files -> `[src/a.ts src/b.ts]`; proposed fix `(@('stash','push','--') + @($files))` -> two arguments. Effect: `git stash push failed - cannot grade`, i.e. failsOnOld=FAIL for every model on any multi-source task, a "measured nothing" outcome like the node3 incident. All 9 current tasks have exactly one entry, so it has never fired. One-line fix, untested on Windows PowerShell 5.1.
2. A fix that creates a NEW source file can't be reverted (`git stash push` ignores untracked files), so failsOnOld keeps the new file. Needs `-u` or deletion.
3. Baseline must be green (`baselineExpect`). Contract-first tasks (tests given, stubs throw `not implemented`) are red by design and need their own task kind: PASS = given tests green + test files unchanged + scope.
4. The typecheck step hard-codes `pnpm exec tsc`; lfc-bot and ASoHaV are npm repos (informational gate, so it degrades silently).
5. Ambient `MANAPOOL_API_KEY` (set in the mining sandbox, and possibly on your desktop) breaks any task whose testCmd includes `tests/services/scryfall.test.ts`. Suggest a per-task `env` block that nulls it.
6. lfc-bot: at some commits (e.g. parent `0548840`) `npm ci` under npm 10.9.7 rejects the lockfile (33 test files fail to load); npm 11 accepts it. Record the required npm in the manifest and check the Windows box.
7. ASoHaV server tests import `@asohav/shared` through its built `dist`, and `setup` runs once, so a model that edits `packages/shared` and is graded by a server test sees a stale build. ASoHaV `apps/web` has no jsdom/testing-library anywhere in history; KaneEnabler (`apps/time-counters`, `apps/home`, `packages/profile`) does.
8. kane-01 pins a mutable branch name; its tip today equals the recorded base `92a8ed0` (one commit on top of main's `54cd6ca`).
